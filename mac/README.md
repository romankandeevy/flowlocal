# FlowLocal для macOS

Нативное приложение (Swift, SwiftUI + AppKit) и бэкенд распознавания на Python
с теми же моделями, что в `../old/`:

- **русский** — GigaAM v3 e2e-rnnt int8 (сама ставит знаки и пишет числа цифрами);
- **английский** — Parakeet TDT 0.6b v2 int8. Переспрос как в old/: GigaAM
  распознаёт всё, и если кусок похож на английский — тот же кусок уходит в
  Parakeet. Определитель — `old/language.py` без изменений плюс правило для
  латиницы: GigaAM v3, в отличие от v2, пишет английскую речь латиницей.

Код не перенесён из `../old/` построчно — перенесены решения: разбор на ходу
(`old/streaming.py`), пороги определителя языка, резка по паузам, ожидание
перед возвратом буфера обмена по длине текста, настройки onnxruntime.

Интерфейс — дизайн-система Verkstad (`prog/_materials`): радиус 0, без теней,
рамки 1/2 px, один акцент в зоне видимости, моно-метки вместо значков, две
равноправные темы. Шрифты системы — Unbounded (заголовки) и Inter (текст) из
Google Fonts, лежат в `Resources/Fonts/` вместе с лицензиями OFL; JetBrains
Mono (метки, клавиши) берётся из `old/assets/fonts/`.

## Сборка и запуск

```bash
./build.sh run
```

Xcode не нужен, хватает Command Line Tools. `build.sh` зовёт `swiftc` напрямую
(SwiftPM на CLT 16.2 под macOS 14 не линкует манифест), при первом запуске
заводит `backend/.venv`; модели докачиваются в `backend/models/` при первом
старте бэкенда (обе папки в `.gitignore`).

**Битые Command Line Tools.** Если CLT обновляли поверх старой версии, в
`/Library/Developer/CommandLineTools/usr/include/swift/` остаётся лишний
`module.modulemap` (его нет в квитанциях установщика, `pkgutil --files
com.apple.pkg.CLTools_Executables`). Он второй раз определяет `SwiftBridging`,
и тогда не собираются CoreFoundation, Foundation, AppKit и SwiftUI, а
компилятор бесконечно перебирает типы нашего кода. `build.sh` прячет этот файл
VFS-оверлеем только для своей сборки — системные файлы не трогаются.

В CLT нет заранее собранных модулей SDK, поэтому первая сборка компилирует
SwiftUI/AppKit в кэш (около полутора минут на двухъядерном Intel). Дальше —
десятки секунд.

`onnxruntime==1.23.2` закреплён намеренно: последняя ветка с колесом под Intel
Mac, и она старше замедления int8 из 1.25 (см. `old/requirements.txt`).

**Постоянная подпись.** Без неё право «Универсальный доступ» слетает после
каждой пересборки (ad-hoc подпись привязана к хэшу бинарника). Один раз:
«Связка ключей» → Ассистент сертификации → Создать сертификат → имя
**FlowLocal Dev**, «Самоподписанный корневой», тип «Подпись кода». `build.sh`
найдёт его сам; после этого право выдаётся один раз навсегда.

## Как пользоваться

- **Зажать — CTRL + SHIFT + SPACE** (как в old/): держите и говорите, отпустили —
  текст встаёт в окно, где вы печатали.
- **Нажать — OPTION + SPACE**: нажали — говорите, нажали ещё раз — текст на
  месте. **Esc** — отмена. Оба сочетания меняются на «Главной» и в настройках.
- Запись — до 30 минут; разбор на ходу держит ожидание около секунды.
- Аудио каждой диктовки сохраняется (`~/Library/Application Support/FlowLocal/
  Recordings`): в истории его можно прослушать и перераспознать. Нераспознанные
  записи тоже попадают в историю.
- Язык: авто (русский + английский по кускам), только русский, только английский.
- Тема — тёмная или светлая, в настройках и в строке меню.

Хоткей — Carbon `RegisterEventHotKey`: ему не нужны ни «Мониторинг ввода», ни
«Универсальный доступ». Разрешения нужны два: **микрофон** (система спросит при
первом запуске) и **универсальный доступ** — для вставки ⌘V в чужое окно; без
него диктовка ложится в буфер обмена.

## Скорость: разбор на ходу

Пока человек говорит, звук уходит в бэкенд порциями по 0,25 с и режется по
паузам в уже сказанном (`server.py`, порт `old/streaming.py`):

- берёмся с 5 с речи; последние 1,8 с не трогаем — человек ещё говорит;
- режем по самой поздней паузе от 0,6 с; паузу в 200 мс берём, только если
  накопилось больше 12 с; кусок не длиннее 10 с; монолог без пауз — в самом
  тихом месте, не по счётчику;
- замолчал до отпускания — остаток разбирается заранее, и если после этого была
  только тишина, ждать нечего вовсе;
- английский переспрашивается по кускам, а не всей записью.

Модели держит один рабочий поток, звук принимает другой: отпускание дожидается
куска в работе, и текст не задваивается (баг old/). Два потока onnxruntime, а
не четыре — замер на этом процессоре: 28,8 с речи за 4,0 с против 5,9 с.

Строка в журнале: `звук=… на_ходу=… хвост=… | ожидание=…` — первые три числа
секунды записи, «ожидание» — секунды работы после отпускания.

## Стабильность

- Номер у каждой диктовки: запоздавший ответ не перебивает новую запись;
  нажатие во время распознавания запись не начинает.
- Потерялось отпускание хоткея (сменился фокус, ввод пароля) — запись всё равно
  закончится по отпущенным модификаторам; предел записи — 5 минут.
- Микрофон — свой движок на каждую запись; сменили устройство посреди фразы —
  движок поднимается заново, записанное сохраняется.
- У каждого запроса к бэкенду свой таймаут. Упал бэкенд посреди работы — запись
  не пропадает: её распознают после перезапуска и положат в буфер.
- Две вставки подряд не теряют исходный буфер обмена: возврат один на всех.
- Протокол бэкенда — на своём дескрипторе: случайный print его не сломает.

## Проверка без приложения

```bash
backend/.venv/bin/python backend/server.py --file запись.wav
```

```bash
backend/.venv/bin/python backend/server.py --stream-file запись.wav
```

Первое — целиком, второе — как при диктовке: порции в реальном времени, в
конце ожидание после «отпускания». Нужен wav 16 кГц 16 бит:
`afconvert -f WAVE -d LEI16@16000 -c 1 in.m4a out.wav`.

## Устройство

Окно — по макету «Flow Local — главный экран» (`prog/_materials`): 1000×680,
тянется (минимум 640×520), вкладки «Главная / История / Статистика /
Настройки». На «Главной» пять состояний: покой, запись с живой расшифровкой,
распознавание, нет микрофона, загрузка моделей. Уже 880 px уходит панель
истории, уже 860 — версия и спокойный статус, уже 700 — знак. Плашка поверх
окон — 360 px у нижнего края экрана.

| Файл | Что делает |
|---|---|
| `Sources/FlowLocal/Controller.swift` | Диктовка целиком: хоткей, запись, разбор на ходу, вставка, плашка, захват сочетания |
| `Sources/FlowLocal/Hotkey.swift` | Глобальные хоткеи (Carbon), нажатие и отпускание отдельно; своё сочетание |
| `Sources/FlowLocal/Recorder.swift` | Микрофон → 16 кГц моно float32, порции для разбора на ходу, уровень |
| `Sources/FlowLocal/AudioDevices.swift` | Список микрофонов (CoreAudio) для выбора входа |
| `Sources/FlowLocal/Backend.swift` | Процесс `backend/server.py` и протокол с ним; живой текст (`partial`) |
| `Sources/FlowLocal/Inserter.swift` | Буфер обмена + ⌘V через CGEvent, возврат прежнего буфера |
| `Sources/FlowLocal/Pill.swift` | Плашка поверх окон: не забирает фокус и мышь |
| `Sources/FlowLocal/MainView.swift` | Корень окна: шапка со вкладками, строка состояния, адаптивность |
| `Sources/FlowLocal/HomeView.swift` | «Главная»: состояния 1a–1e, панель истории, микрофон, плитки |
| `Sources/FlowLocal/TabsViews.swift` | «История» (поиск, вставить, удалить), «Статистика», «Настройки» |
| `Sources/FlowLocal/Components.swift` | Примитивы Verkstad: кнопка, вкладки, переключатель, флажок, выбор, прогресс, скелетон |
| `Sources/FlowLocal/Theme.swift` | Токены Verkstad: палитры, шкалы, движение, шрифты |
| `Sources/FlowLocal/AppState.swift` | Состояние окон, настройки, статистика из истории |
| `Sources/FlowLocal/Log.swift` | Журнал `~/Library/Logs/FlowLocal.log` с ротацией |
| `backend/server.py` | Модели, разбор на ходу, живой текст, переспрос на английский |
| `backend/langdetect.py` | Определитель английского из `old/language.py` |
