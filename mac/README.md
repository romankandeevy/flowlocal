# FlowLocal для macOS

Нативное приложение (Swift, SwiftUI + AppKit) и бэкенд распознавания на Python
на моделях onnx-asr:

- **русский** — GigaAM v3 e2e-rnnt int8 (сама ставит знаки и пишет числа цифрами);
- **английский** — Parakeet TDT 0.6b v2 int8. GigaAM
  распознаёт всё, и если кусок похож на английский — тот же кусок уходит в
  Parakeet. Определитель английского по словарю плюс правило для
  латиницы: GigaAM v3, в отличие от v2, пишет английскую речь латиницей.

## Сборка и запуск

```bash
./build.sh install
```

Собирает, кладёт в `/Applications` (нет прав — в `~/Applications`) и
запускает. Дальше приложение открывается как любое другое — из Launchpad,
Spotlight или Дока. `./build.sh run` — собрать и запустить прямо из
`build/`, для разработки.

`./build.sh dmg` — образ для релиза `build/FlowLocal-<версия>.dmg`: один
бинарник под arm64 и x86_64 (lipo), подпись ad-hoc, окружение этого Мака не
нужно. Python приложение из .dmg заводит само при первом запуске
(`PythonSetup.swift`). Проверить первый запуск, не трогая свои данные:
`FLOWLOCAL_SUPPORT_DIR=/tmp/fl-test` — другая папка данных.

Сборка переносима: ни одного абсолютного пути ни в `.app`, ни в скриптах —
репозиторий может лежать где угодно, `.app` можно положить в «Программы» или
переслать. Всё, что зависит от конкретного Мака, живёт в данных пользователя:

| Где | Что |
|---|---|
| `build/FlowLocal.app/Contents/Resources/backend/` | `server.py`, `langdetect.py` — бэкенд едет внутри приложения |
| `~/Library/Application Support/FlowLocal/Python/` | окружение бэкенда, своё на каждом Маке |
| `~/Library/Application Support/FlowLocal/Models/` | модели, докачиваются при первом старте |
| `~/Library/Application Support/FlowLocal/Recordings/` | звук диктовок |
| `~/Library/Logs/FlowLocal.log` | журнал |

Пути собраны в одном месте — `Sources/FlowLocal/Paths.swift`. Чтобы править
бэкенд без пересборки: `FLOWLOCAL_BACKEND_DIR=$PWD/backend open build/FlowLocal.app`.

`build.sh` сам:

- **выбирает тулчейн** — Xcode, если он установлен (даже когда `xcode-select`
  смотрит на Command Line Tools), иначе CLT. На свежих SDK `@State` в SwiftUI —
  макрос, и его плагин есть только в Xcode; на SDK постарше хватает CLT;
- **находит Python 3.11–3.13** (brew, python.org, pyenv, `PATH`; свой можно
  указать: `PYTHON=/путь/python3 ./build.sh`). Нет подходящего, но есть
  Homebrew — ставит `python@3.13`;
- **проверяет окружение**, а не только наличие файла: скопированное с другого
  Мака (ссылки на чужой Python) или устаревшее по `backend/requirements.txt`
  заводится заново;
- переносит модели из прежней `backend/models/`, если они там остались.

**Битые Command Line Tools.** Если CLT обновляли поверх старой версии, в
`/Library/Developer/CommandLineTools/usr/include/swift/` остаётся лишний
`module.modulemap` (его нет в квитанциях установщика, `pkgutil --files
com.apple.pkg.CLTools_Executables`). Он второй раз определяет `SwiftBridging`,
и тогда не собираются CoreFoundation, Foundation, AppKit и SwiftUI, а
компилятор бесконечно перебирает типы нашего кода. `build.sh` прячет этот файл
VFS-оверлеем только для своей сборки — системные файлы не трогаются.

В CLT нет заранее собранных модулей SDK, поэтому первая сборка компилирует
SwiftUI/AppKit в кэш (около полутора минут на двухъядерном Intel). Дальше —
десятки секунд.

`onnxruntime==1.23.2` закреплён намеренно: последняя ветка с колесом под Intel
Mac, и она старше замедления int8 из 1.25.

**Постоянная подпись.** Без неё право «Универсальный доступ» слетает после
каждой пересборки (ad-hoc подпись привязана к хэшу бинарника). Один раз:
«Связка ключей» → Ассистент сертификации → Создать сертификат → имя
**FlowLocal Dev**, «Самоподписанный корневой», тип «Подпись кода». `build.sh`
найдёт его сам; после этого право выдаётся один раз навсегда.

## Как пользоваться

- **Зажать — CTRL + SHIFT + SPACE** : держите и говорите, отпустили —
  текст встаёт в окно, где вы печатали.
- **Нажать — OPTION + SPACE**: нажали — говорите, нажали ещё раз — текст на
  месте. **Esc** — отмена. Оба сочетания меняются в Hub Settings (⌘, во Flow) →
  Flow → «Сочетания клавиш».
- Запись — до 30 минут; разбор на ходу держит ожидание около секунды.
- Аудио каждой диктовки сохраняется (`~/Library/Application Support/FlowLocal/
  Recordings`): в истории его можно прослушать и перераспознать. Нераспознанные
  записи тоже попадают в историю.
- Язык: авто (русский + английский по кускам), только русский, только английский.
- **Стиль под приложение** (вкладка «Стиль» в окне): Обычный, Переписка (с
  маленькой буквы, без точки), Письмо (строго, с точкой), Код (как сказано, без
  пробела после вставки). Приложение — то, что было впереди в начале записи.
- **Словарь** (вкладка «Словарь»): имена и термины; похожее на слух слово
  ставится так, как записано («гитхаб» → GitHub).
- **Учится на исправлениях**: правка в истории («Исправить…») или прямо в поле
  после вставки — пара «было → стало» запоминается и применяется дальше.
  Поле читается через Универсальный доступ только после своей вставки, до
  полутора минут; пароли — никогда.
- **Режим шёпота** (сайдбар, ⌥⌘W): на время записи чувствительность микрофона
  поднимается до максимума и возвращается после; плюс мягкое усиление.
- Тема — как в системе: светлая (почти белая) или тёмная (графит), акцент —
  яркий зелёный.

Хоткей — Carbon `RegisterEventHotKey`: ему не нужны ни «Мониторинг ввода», ни
«Универсальный доступ». Разрешения нужны два: **микрофон** (система спросит при
первом запуске) и **универсальный доступ** — для вставки ⌘V в чужое окно; без
него диктовка ложится в буфер обмена.

## Скорость: разбор на ходу

Пока человек говорит, звук уходит в бэкенд порциями по 0,25 с и режется по
паузам в уже сказанном (`server.py`):

- берёмся с 5 с речи; последние 1,8 с не трогаем — человек ещё говорит;
- режем по самой поздней паузе от 0,6 с; паузу в 200 мс берём, только если
  накопилось больше 12 с; кусок не длиннее 10 с; монолог без пауз — в самом
  тихом месте, не по счётчику;
- замолчал до отпускания — остаток разбирается заранее, и если после этого была
  только тишина, ждать нечего вовсе;
- английский переспрашивается по кускам, а не всей записью.

Модели держит один рабочий поток, звук принимает другой: отпускание дожидается
куска в работе, и текст не задваивается. Потоков onnxruntime — по производительным ядрам,
не больше четырёх: на M4 91 с речи — 1,46 с на четырёх против 2,08 с на двух;
на двухъядерном Intel — два.

Строка в журнале: `звук=… на_ходу=… хвост=… | ожидание=…` — первые три числа
секунды записи, «ожидание» — секунды работы после отпускания.

## Стабильность

- Номер у каждой диктовки: запоздавший ответ не перебивает новую запись;
  нажатие во время распознавания запись не начинает.
- Потерялось отпускание хоткея (сменился фокус, ввод пароля) — запись всё равно
  закончится по отпущенным модификаторам; предел записи — 30 минут.
- Микрофон — свой движок на каждую запись; сменили устройство посреди фразы —
  движок поднимается заново, записанное сохраняется.
- У каждого запроса к бэкенду свой таймаут. Упал бэкенд посреди работы — запись
  не пропадает: её распознают после перезапуска и положат в буфер.
- Две вставки подряд не теряют исходный буфер обмена: возврат один на всех.
- Протокол бэкенда — на своём дескрипторе: случайный print его не сломает.

## Проверка без приложения

```bash
~/Library/Application\ Support/FlowLocal/Python/bin/python3 backend/server.py --file запись.wav
```

```bash
~/Library/Application\ Support/FlowLocal/Python/bin/python3 backend/server.py --stream-file запись.wav
```

Первое — целиком, второе — как при диктовке: порции в реальном времени, в
конце ожидание после «отпускания». Нужен wav 16 кГц 16 бит:
`afconvert -f WAVE -d LEI16@16000 -c 1 in.m4a out.wav`.

## Устройство

Главное окно — одно (`Window`, без заголовка; размер и место macOS запоминает
сама). Слева сайдбар: разделы «Главная / История / Обзор / Стиль / Словарь»
(⌘1…⌘5), неделя, переключатель шёпота и готовность распознавания. Стиль и
словарь настраиваются в самом окне; остальные настройки — в Hub Settings
(`apps/hub-settings`), ⌘, открывает его сразу на модуле Flow. Хаб пишет UserDefaults Flow и шлёт
уведомление `com.roman.suite.flow.settings`, Flow подхватывает изменения на лету
(`HubSync.swift`).

- **Главная** — приветствие, четыре числа за день, диктовки сегодня; щелчок по
  строке копирует. Во время записи — живая расшифровка. Пока диктовок нет —
  первые шаги.
- **История** — календарь диктовок как на GitHub (щелчок по дню — только его
  диктовки; столбик на графике «Обзора» ведёт туда же), поиск (⌘F), фильтры по
  языку и нераспознанным, дни карточками. Текст хранится весь в
  `~/Library/Application Support/FlowLocal/history.json`, звук — у последних 500.
  В списках: стрелки, **↩** — вставить, **пробел** — прослушать, ⌘C, ⌫ и
  «Отменить»; «⋯» и правый щелчок — остальные действия.
- **Обзор** — слова за неделю или месяц, график по дням, итог за всё время.

Индикатор записи — капсула поверх окон у края экрана: чёрная плашка и белые
полоски бегущей волны, больше ничего; не настраивается.

Логику без окна проверяет `tools/selftest.sh`: словарь, обучение на правках,
стили, режим шёпота.
